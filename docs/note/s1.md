# S1 阶段复盘：单进程 Agent 闭环与事件广播

> 对应决策：无（S1 未单独产出 ADR，相关结论并入 S0 / S2）

## 理解：一次 run 的数据流

```text
CLI → core 守护进程 → AgentRunner（负责编排）
                        ├─ 生成 run_id
                        ├─ 建立 EventBus
                        └─ 创建 AgentLoop（组装 tool / provider / event 定义）
                              ↓ step 过程中 loop 与 runner 向 EventBus 发消息
                           EventBus 分发给订阅者
                              ├─ 写本地 event.jsonl 的 writer
                              └─ CLI 中在终端输出内容的类
```

## 发现

1. **AgentLoop 目前更偏 ReAct。** 每做一步都要 plan 一下，后续可以改造成 plan-and-execute，或两者结合的框架。

2. **loop 过程中不支持用户插入对话。** 缺少 WebSocket 这类双向通道，用户无法在 loop 运行期间实时干预 agent 的行为。

## 遗留

- CLI 与 core 同机，因此直接复用了 S0 的 socket；按 S0 的结论把通信协议改成 HTTP server 后，CLI 才真正回到客户端位置。
