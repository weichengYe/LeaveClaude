今天下午把s1相关的内容看完了 也跑了一遍。我个人理解是1.CLI-》守护进程core-》agent runner（用于编排）-》runner生成run-id 、建立eventbus用于广播事件，创建agent-loop进行正式循环（这里涉及到tool，provider，event等的定义创建）-》在step的过程中loop和runner向event-bus传播消息，然后由event-bus向订阅他的类发送消息，如写本地event.jsonl日志的类,cli中在终端输出内容的类。
这里由于cli和core在一台服务器上，直接复用了之前的socket，cli实际上应该在客户端，这里在s0中将通信协议改成http server协议即可。
发现1.s1目前agent-loop的设计更偏向react的框架，每做一步都要plan一下，后续可能可以改造成plan-and-excute 或者 二结合的框架
发现2 s1目前的loop中似乎并不支持在loop的过程中接受用户的插入对话 也即使用websocket的双向通信，让用户可以在loop的过程中实时对agent行为进行干涉，后续可以继续看看 如何改进
